# 05 · 各类型照片要求与引导文案

> 实现位置：`src/modules/*/capture.config.ts`（阈值与检查项）、`src/copy/capture.zh-CN.ts`（文案）


> **相机路径会连拍 5 帧**（≈0.6 秒，用户无感）。同一机位、同一角度，
> 目的不是拿新信息，而是把逐帧都在变的噪声平均掉：传感器噪声、微动模糊、
> 一瞬间的表情、自动曝光浮动，以及关键点检测器自身的抖动。
> 几何量逐叶取中位数，帧间离散度换算成置信度乘数（`core/frames.ts`）。
> 相册上传没有这个条件，走单帧路径，行为与以前完全一致。
> 连拍帧与单张一样只在内存里，取完关键点立刻 `close()`，不落盘、不上传。

## 一、通用质量门控

所有类型进入特征提取前，都要过同一套闸门。检测失败时**不阻断**，而是降低对应特征的
`confidence` 并在 `capture.quality.issues` 中写入人类可读的提示。

| 检查 | 方法 | 阈值 | 未通过时 |
|---|---|---|---|
| 分辨率 | 主体（脸/手/人）在画面中的像素宽 | ≥ 400px | `resolution: "low"`，全局 confidence × 0.8 |
| 清晰度 | Laplacian 方差 | ≥ 100 | `sharpness: "blurry"`，× 0.7；< 40 则拒绝 |
| 亮度 | 主体区域平均 L\* | 35 ≤ L ≤ 85 | `lighting: "dim"/"harsh"`，气色项 × 0.5 |
| 色偏 | 全图 a\*/b\* 中位数偏离 | \|a\*\| < 8 且 \|b\*\| < 15 | `lighting: "color_cast"`，气色项直接 `unavailable` |
| 强阴影 | 主体区域亮度直方图双峰性 | 双峰间距 < 40 | 阴影侧特征 × 0.6 |
| 主体数量 | 检测结果数 | = 1 | 多于 1 个时要求用户选择或重拍 |
| 逆光 | 背景 L\* − 主体 L\* | < 40 | 提示「背对窗户会逆光」 |

> **拒绝而非降级的唯一情况**：清晰度极低（Laplacian 方差 < 40）或未检测到主体。
> 其余一律降级 + 提示，让用户自己决定是否重拍——强行拦截很伤转化。

## 二、面相（Mianxiang）

### 需要的照片
**1 张正面人脸照**

### 硬性要求
| 项 | 要求 | 检测方式 |
|---|---|---|
| 姿态 | \|yaw\| ≤ 15°，\|pitch\| ≤ 12°，\|roll\| ≤ 10° | `facialTransformationMatrixes` 分解欧拉角 |
| 表情 | 自然平静，不笑不皱眉 | `faceBlendshapes` 中 `mouthSmile*`、`browDown*` < 0.3 |
| 遮挡 | 额头、眉、眼、鼻、口全部可见 | 关键点可见性 + 分割掩膜 |
| 距离 | 人脸宽 ≥ 画面宽 30% | 人脸框宽度 |
| 光线 | 正面均匀漫射光 | 见通用门控 |

### 建议但不强制
- 头发撩起露出额头（影响上停与官禄宫、迁移宫、父母宫）
- 摘掉眼镜（影响眼型、卧蚕、田宅宫）
- 素颜或淡妆（影响气色）

### 引导文案

**拍摄页标题**：`拍一张正面照`

**要点清单**（拍摄页三条）：
```
· 正对镜头，不低头不抬头，表情自然放松
· 光线均匀，别背对窗户，也别在头顶强光下
· 露出额头和双眉，方便看三停与十二宫
```

**实时提示**（相机预览时根据检测结果动态显示）：
| 状态 | 文案 |
|---|---|
| 未检测到人脸 | `把脸放进取景框里` |
| yaw 超限 | `头再正一点，正对镜头` |
| pitch 超限（低头） | `下巴稍微抬一点` |
| pitch 超限（抬头） | `下巴稍微收一点` |
| 太远 | `再靠近一些，让脸占满取景框` |
| 太暗 | `光线有点暗，换个亮一些的地方` |
| 逆光 | `背后有强光，转个方向试试` |
| 微笑幅度大 | `放松，自然一点就好` |
| 全部通过 | `很好，可以拍了` ✅ |

**遮挡提醒**（检测到时，非阻断）：
- `刘海挡住了额头，撩一下可以看得更准（也可以直接拍）`
- `戴眼镜会影响眼部的判断，方便的话摘一下`

**隐私提示**（首次进入拍摄页）：
```
照片只在你的手机里处理，不会上传。
分析结束后，只有算出来的数字特征会发给 AI 生成解读。
```

## 三、手相（Shouxiang）

### 需要的照片
**1–2 张手掌照**。引导优先拍**惯用手**；两只手都拍可以做先天/后天对照（加分项，不强制）。

### 硬性要求
| 项 | 要求 | 检测方式 |
|---|---|---|
| 手掌朝向 | 掌心正对镜头，掌平面法向与视轴夹角 ≤ 20° | 由 0/5/17 三点构成的平面法向 |
| 手指 | 五指自然张开，不并拢不弯曲 | 指间距 / 掌宽 ≥ 0.15；各指 MCP-PIP-TIP 近共线 |
| 完整性 | 从腕横纹到指尖全部入镜 | 21 点全部 `visibility` 高且在画面内 |
| 尺寸 | 手掌区域 ≥ 画面面积 35% | 掌四边形面积 |
| 光线 | **柔和漫射光，无直射硬光** | 关键：硬光会打死掌纹对比 |
| 背景 | 深色纯背景最佳 | 便于手部轮廓分割 |

### 掌纹专属提示（本模块成败关键）

掌纹提取对光线的敏感度**远高于**其他模块。文案必须讲清楚：

```
· 掌心朝上摊平，手指自然张开，别用力绷直
· 别在正午阳光或射灯下拍——硬光会把掌纹拍没
· 靠窗的散射光、或者阴天的室外，效果最好
· 手别离镜头太近，容易糊焦
```

### 引导文案

**拍摄页标题**：`拍一张手掌照`

**手别选择**：`先拍哪只手？` → `[惯用手（推荐）] [左手] [右手]`
选完后提示：`左手看先天禀赋，右手看后天努力。两只都拍可以做对照。`

**实时提示**：
| 状态 | 文案 |
|---|---|
| 未检测到手 | `把手掌放进框里，掌心朝向镜头` |
| 手背朝向 | `翻过来，掌心对着镜头` |
| 平面角超限 | `手掌放平一点，别倾斜` |
| 手指并拢 | `五指自然张开一点` |
| 手指弯曲 | `手指伸直，别用力绷` |
| 不完整 | `手腕和指尖都要入镜` |
| 太小 | `手再靠近一点` |
| 硬光/高光过曝 | `光太硬了，掌纹会看不清，换个柔和的光` |
| 全部通过 | `很好，保持住` ✅ |

**掌纹校正页**（`matchScore < 0.45` 时进入）：

标题：`帮我确认一下掌线`
说明：
```
你的掌纹有几条不太好自动辨认。下面是识别到的线条，
点一下线，再选它是哪条主线；也可以直接用手指描一条。
不确定的话跳过就好，我会如实标注为「未测到」。
```
按钮：`[生命线] [智慧线] [感情线] [命运线] [不确定，跳过]`

底部提示：`跳过不影响出报告，只是这条线不会被解读。`

## 四、骨相（Guxiang）

### 需要的照片
**2 张人脸照（正面 + 侧面）**，可选第 3 张半身/全身照。

这是四个模块里唯一需要多张照片的，必须在入口就讲清楚，否则用户拍完正面才发现还要侧面会流失。

### 硬性要求

**正面照**：同面相，另加：
| 项 | 要求 |
|---|---|
| 头发 | 尽量露出额头与太阳穴（影响额骨、颞骨） |
| 表情 | 不咬肌用力（影响下颌角测量） |

**侧面照**：
| 项 | 要求 | 检测方式 |
|---|---|---|
| 角度 | yaw 在 75°–105° 之间（正侧面） | 欧拉角 |
| 完整性 | 从额顶到下颌、耳部可见 | 关键点边界 |
| 头发 | 尽量把耳朵与鬓角露出来 | 提示，不检测 |

**体照（可选）**：同体相要求。

### 引导文案

**入口说明页**（进入拍摄前必看）：
```
关于骨相，先说清楚三件事：

1. 需要两张照片：一张正面，一张侧面。
   侧面照用来看头部前后径，没有它就判断不了头型。

2. 骨相看的是骨架，但照片拍不到骨头。
   我们是从你的面部轮廓、下颌线条、肩线这些体表信息，
   反过来推算骨架的特征——所以这是「推估」，不是「测量」。

3. 传统九骨里的枕骨（后脑）、顶骨（头顶）、耳后骨，
   任何照片都看不到，我们不会瞎猜，报告里会如实写明「未观测」。
```
按钮：`[明白了，开始拍]`

**正面照提示**：同面相，追加 `别咬牙，放松下巴`

**侧面照提示**：
| 状态 | 文案 |
|---|---|
| 角度不足 | `再转过去一点，拍完整的侧脸` |
| 角度过头 | `转回来一点，别拍到后脑勺` |
| 头发遮耳 | `把头发别到耳后，可以看得更准` |
| 通过 | `侧面很标准` ✅ |

**可选体照**：
```
再加一张半身或全身照，可以一起看肩骨、脊椎和骨盆。
不拍也行，只是这几项会标为「未采集」。
[拍一张] [跳过]
```

## 五、体相（Tixiang）

### 需要的照片
**1 张全身照**（次选半身，此时下肢相关项标 `not_captured`）

### 硬性要求
| 项 | 要求 | 检测方式 |
|---|---|---|
| 完整性 | 头顶到脚踝全部入镜 | 关键点 0 与 27/28 均在画面内且 visibility > 0.6 |
| 朝向 | 正面站立 | 双肩 z 差 / 肩宽 < 0.2 |
| 姿势 | 自然站直，双臂自然下垂或微微张开 | 肘角 > 150°；腕不遮挡躯干 |
| 人数 | 画面中仅 1 人 | Pose 检测结果数 |
| 相机 | 镜头高度约在腰部，避免俯拍仰拍 | 由关键点透视畸变估计，仅提示 |
| 服装 | 合身，非宽松罩袍 | 无法检测，仅文案提示 |

### 引导文案

**拍摄页标题**：`拍一张全身照`

**要点清单**：
```
· 从头到脚都要拍进去，正面站直
· 双手自然垂在身侧，别插兜、别抱臂
· 穿合身一点的衣服，宽松外套会看不出体态
· 找人帮忙拍，或者把手机架在腰高的位置用定时
```

**实时提示**：
| 状态 | 文案 |
|---|---|
| 未检测到人 | `站到取景框里` |
| 脚未入镜 | `往后退一点，脚也要拍到` |
| 头未入镜 | `手机再往上一点` |
| 侧身 | `正对镜头站好` |
| 抱臂/插兜 | `手臂自然垂在身体两侧` |
| 多人 | `画面里只留一个人` |
| 俯拍/仰拍 | `手机放到腰的高度，平着拍` |
| 通过 | `站好别动，3、2、1` ✅ |

**半身降级提示**：
```
只拍到上半身也可以，不过腿部比例、站姿重心这些项会标为「未采集」。
[就这样分析] [重拍全身]
```

**自评问卷**（分析后、生成报告前，可跳过）：

标题：`还有三个问题，照片看不出来`
```
1. 你的声音更接近？   [洪亮] [柔和] [低沉] [清亮]
2. 你说话的节奏？     [偏快] [适中] [偏慢]
3. 日常穿着更偏向？   [整洁得体] [随意自然] [时尚前卫] [传统保守] [朴素简约]
```
底部：`[跳过，直接出报告]`
提示：`这几项在《冰鉴》里属于「神」的部分，填了会更完整。`

## 六、权限与失败处理

| 场景 | 处理 |
|---|---|
| 首次请求相机权限 | 先出一个说明页解释「为什么需要相机 + 照片不上传」，再触发系统弹窗（避免冷启动被拒） |
| 权限被拒 | 不死循环请求。展示：`没有相机权限也可以，从相册选一张就行` + 上传按钮 |
| 权限被永久拒绝 | 展示各平台的设置路径指引（iOS Safari / Android Chrome 分别给图文） |
| 无相机设备（桌面） | 直接展示上传区，支持拖拽与粘贴 |
| 模型下载失败 | 重试 2 次 → 提示 `模型没下下来，检查一下网络？` + 重试按钮；已缓存则走缓存 |
| 模型下载中 | 进度条 + `正在准备（约 4 MB，只需下载一次）` |
| 检测不到主体 | `没找到脸/手/人，换一张试试` + 显示要求清单 |
| 特征提取异常 | 捕获并降级：能算出多少算多少，`unavailable` 里写明原因，仍然出报告 |
| AI 请求失败 | 保留已提取的特征（存 IndexedDB），提供 `重试` + `稍后再看`；特征不丢 |
| 未配置 API Key | 引导到设置页，附各家 Key 的申请链接与免费额度说明 |

## 七、上传路径（非拍摄）

四种类型都必须支持从相册选图，因为：
- 全身照几乎不可能自拍
- 桌面端没有合适的相机
- 用户可能想分析已有的照片

上传后的处理与拍摄完全一致（同样的质量门控、同样的实时提示改为静态检查结果）。

**EXIF 处理**：读取 `Orientation` 做旋转校正后，**剥离全部 EXIF**（含 GPS）再进入处理管线。
即使照片不上传，也不要让地理位置进入内存中的可导出对象。

**尺寸处理**：长边 > 1920px 时先等比缩放到 1920（保证检测精度的同时控制内存），
掌纹管线在缩放前的原图上跑（需要细节）。
