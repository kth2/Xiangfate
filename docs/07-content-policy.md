# 07 · 内容安全策略与免责设计

> 规则来源 kanxiang 的四个知识库里，有相当一部分内容**不适合直接放进一个面向公众的 App**。
> 本文件逐条列出问题项与改写方案，并定义全套防线。
> 机器可执行版本：`src/core/guard.rules.ts`。
>
> 求测者实际会问的问题、以及传统术士的答法，整理在
> [`docs/xiangshu-qa-knowledge.md`](./xiangshu-qa-knowledge.md)；
> 那份知识库与本文件冲突时**一律以本文件为准**，冲突项列在它的第 7 节。

---

## 一、为什么需要这一层

kanxiang 是一个给开发者自己用的 Claude Code Skill，受众窄、语境明确。而我们要做的是
**任何人都能装到手机上的 App**，其中包含：

- 会认真对待结果的用户（相术内容可能真的影响他们的决定）
- 未成年人
- 正处在情绪低谷的人

传统相书成书于千百年前，包含大量在今天看来是**人格污名、性别歧视、身材歧视、
医疗断言**的内容。原样搬运既不负责任，也会带来实际的产品风险。

**处理原则**：保留传统相术的**框架、术语、观察角度与文化趣味**，剔除其中的
**贬损性判断与伪医学断言**。「三停平均主运势平稳」可以留；「耳小薄削主短命」必须删。

## 三、四道防线

内容安全不能只靠 Prompt。四层，任一层单独失效不至于出事：

### 第 1 层：数据源头
`meaning` 字段直接来自 `rules.ts` 中**已经改写过的**文案。有问题的原文根本不进入代码库。
→ AI 拿到的 JSON 里就没有「短命」「克夫」这类词。

### 第 2 层：Prompt 约束
System Prompt 中的禁用词表、禁止内容清单、`unavailable` 硬边界、措辞强度对照表。
见 `04-prompts.md` 第二节。

### 第 3 层：输出后置校验（`core/guard.ts`）
AI 输出在渲染前必过。这是唯一一道**不依赖模型配合**的防线。

```ts
// core/guard.rules.ts 的结构
export const BANNED_ABSOLUTE = [
  '必定','一定','肯定','注定','必有','绝对','无疑','势必','终将',
  '逃不过','命中注定','铁定','难逃'
];

export const BANNED_FATE = [
  '短命','长寿之相','夭折','寿元','阳寿','大限','死于','活不过',
  '克夫','克妻','克子','丧偶','离异之相','孤独终老','绝后','难产'
];

export const BANNED_STIGMA = [
  '心术不正','薄情','寡义','阴险','狡诈','奸猾','小人相','凶相',
  '刻薄相','贱','低贱','愚钝','蠢','懒惰','软弱','没出息'
];

export const BANNED_MEDICAL = [
  '肝胆','肾虚','肾气不足','心血管','糖尿病','高血压','癌','肿瘤',
  '结石','炎症','病变','确诊','诊断','病灶','慢性病','免疫力低下',
  '内分泌失调','贫血','骨质疏松'
];

export const BANNED_DISCRIMINATION = [
  '矮个子','高个子','肥胖','太胖','太瘦','丑','难看','残疾'
];

export const BANNED_GENDERED = [
  '女人就该','男人就该','女命主','旺夫','宜嫁','嫁得好','娶妻'
];

export const BANNED_TIME_PREDICTION = /(今年|明年|后年|\d{4}\s*年|\d+\s*岁时|下半年|上半年|\d+\s*月)(会|将|有|遇|逢|主)/;
```

| 命中类型 | 动作 |
|---|---|
| `BANNED_ABSOLUTE` | 触发一次重生成（附加纠正指令）；再次命中则删除该句 |
| `BANNED_FATE` / `BANNED_MEDICAL` / `BANNED_STIGMA` / `BANNED_DISCRIMINATION` / `BANNED_GENDERED` | **直接删除整句**，不重生成（避免二次风险），记录审计日志 |
| `BANNED_TIME_PREDICTION` | 删除该句 |
| 出现 `unavailable` 中的 label | 删除该句，记录告警（说明 Prompt 约束失效，需调查） |
| 缺必需二级标题 / 长度异常 | 重生成一次 |

若删句后某小节内容 < 50 字，整节替换为：
`（本次测得的特征不足以就这一部分展开，暂略。）`

### 第 4 层：UI 层强制
- 免责声明由 App 渲染，**不经过 AI**，因此不可能被绕过（`04-prompts.md` 第五节）
- 星级评分由本地 `scorecard.ts` 算出，AI 不参与
- 报告页顶部固定一条常驻横幅（见下）

## 四、免责声明的三个层次

### 4.1 首次启动（一次性，必须点击确认）

```
关于「相由」，有几句话想先说清楚

这是一个把传统相术当作文化来玩的应用。

· 相术是传统文化，不是科学。它对性格、运势的预测能力，
  现代科学并没有证实。
· 这里的所有内容仅供娱乐和文化参考，不构成任何决策建议。
  请不要用它来决定工作、感情、健康或者任何重要的事。
· 你的照片只在这台设备上处理，不会上传。只有算出来的
  数字特征（比如「三停比例 34% : 33% : 33%」）会发给 AI
  用来生成解读文字。
· 请只分析你本人的照片，或者已经取得对方同意的照片。
· 本应用不面向未成年人。

                        [我明白了]
```

### 4.2 报告页常驻横幅（不可关闭）

```
⚠️ 传统文化解读，仅供娱乐参考，不构成任何决策建议
```

### 4.3 报告底部完整声明

见 `04-prompts.md` 第五节。分享出去的卡片、导出的图片都必须带上短版：
> 仅供娱乐与传统文化参考，不构成任何决策建议。

## 五、特殊场景处理

| 场景 | 处理 |
|---|---|
| **疑似未成年人照片** | Face Landmarker 无年龄输出，无法可靠判定。做法：① 首启声明写明不面向未成年人；② `subject.ageBand` 若用户选了 `18 岁以下`，直接不进入分析，提示「本应用不面向未成年人」；③ 不做自动年龄推断（准确率不足，误判伤害更大） |
| **非本人照片** | `subject.isSelf` 让用户确认。选「否」时提示：「请确保已获得对方同意」。不做人脸比对（会引入更多隐私问题） |
| **追问涉及重大人生决定**（是否离婚、是否辞职、是否放弃治疗） | Prompt 中已定义：停止相术解读，表达关心并建议寻求身边的人或专业人士支持。同时前端做关键词检测，命中时在回复上方插入一张固定的关怀卡片 |
| **用户情绪低落 / 提及自伤** | 前端关键词检测优先于 AI 回复。直接展示关怀卡片 + 求助资源，**不发送该轮请求给 AI** |
| **用户反复追问求确定答案** | Prompt 中要求转回「传统相法怎么看 + 你可以怎么做」 |
| **AI 服务返回拒绝/空** | 展示：「这次没能生成解读，换个问法或稍后再试」+ 保留已提取的特征 |

**关怀卡片文案**（`src/copy/care.zh-CN.ts`）：
```
听起来你现在可能不太好过。

相术是拿来玩的，不该拿来做这么重要的决定。
如果你正在经历一些难处，跟信任的人聊聊，
或者找专业的心理咨询，都会比看相有用得多。

如果情况紧急，请联系当地的心理援助热线。
```

> 具体热线号码按发布地区配置，不硬编码在通用文案里。

## 六、隐私承诺（必须做到，不只是写在文档里）

| 承诺 | 技术保障 |
|---|---|
| 照片不上传 | 全部处理在浏览器；`ai/provider.ts` 只接受 `AnalysisEnvelope`，**类型上就无法传入图像** |
| 照片不落盘 | `ImageBitmap` 用完显式 `close()`；IndexedDB schema 中**没有**图像字段 |
| 剥离 EXIF | 上传路径读取 Orientation 后立即剥离全部 EXIF（含 GPS） |
| 不发送 landmark 原始坐标 | `AnalysisEnvelope` 中没有坐标字段；478×3 浮点数理论上可反推面部几何 |
| 历史记录本地存储 | IndexedDB，不同步任何服务器 |
| 一键清除 | 设置页提供「清除所有历史记录」，同时清 IndexedDB 与 Cache Storage |
| API Key 本地存储 | `localStorage`，不上传；代理模式下前端根本不接触 Key |
| 无埋点 | MVP 不接入任何分析 SDK。若日后加，必须默认关闭 + 明确告知 |

**README 中要写清楚**：BYO Key 模式下 Key 存在浏览器里且会随请求发往 AI 服务商；
公开部署必须用代理模式。

## 七、审计与迭代

- `guard.ts` 每次拦截都写一条本地审计日志（不含用户内容，只含规则 ID 与命中类型）
- 设置页提供「导出审计日志」，便于开发期发现 Prompt 漏洞
- `BANNED_*` 词表随实际拦截情况持续补充
- 每次修改 `rules.ts` 中的 `meaning` 文案，都要对照本文档 checklist 过一遍
